## 로컬 실행

`index.html`을 브라우저로 열면 바로 동작합니다. (설치·빌드 불필요)
로컬 확인용으로는 아래처럼 띄울 수 있습니다.

```
npx http-server -p 8080
```

> 저장 기능(localStorage)은 `http(s)://`로 접속할 때 가장 안정적입니다.
> `file://`로 직접 열면 브라우저·설정에 따라 저장이 차단될 수 있으며,
> 이 경우 앱이 시작 화면에 경고를 표시하고 게임 진행만 가능합니다.
> 실제 수업에서는 위 배포 주소를 사용하세요.

## 진행 흐름

1. **팀 선택** — 레드팀 / 옐로팀 / 블루팀
2. **조 이름 입력** — 예) `1` 입력 시 "레드팀 1조"로 셋팅
3. **셋팅 확인** — 초기 칩 25개 지급 안내 및 규칙 안내
   - 5개 라운드 동안 25개의 칩에서 배팅
   - 우리 조가 우승하려면 먼저 우리 팀이 승리해야 함
   - 팀 승리 → 칩을 많이 배팅 / 조 우승 → 칩을 많이 남김
4. **라운드 1~5 반복**
   - `N라운드 시작` 버튼
   - 배팅할 칩 입력 (남은 칩 수를 초과할 수 없음)
   - "남은 칩의 갯수는 00개 입니다. 칩을 배팅하시겠습니까?" 확인
     - **예** → "N개의 칩을 배팅하였습니다. 남은 칩의 갯수는 00개 입니다."
     - **아니오** → 칩 갯수 재입력
5. **조기 종료** — 3라운드부터 각 라운드 결과 화면에 `여기서 종료하고 결과 저장` 노출
   (3승 팀이 나와 게임이 끝나면 5라운드를 채우지 않고 저장)
6. **최종 결과** — 남은 칩의 갯수 + 진행한 라운드 기록 + 자동 저장

## 조별 결과 저장

브라우저 `localStorage`에 저장합니다. 서버가 없으므로 **저장한 그 기기에서만** 보입니다.

| 항목 | 저장 키 | 내용 |
|---|---|---|
| 완료 기록 | `chipDilemma.records.v1` | 팀, 조, 라운드별 배팅, 총 배팅, 잔여 칩, 저장 시각 |
| 진행 상태 | `chipDilemma.progress.v1` | 현재 팀·조·라운드·잔여 칩 (완료 또는 재시작 시 삭제) |

- **자동 저장** — 5라운드를 마치거나 조기 종료하면 결과가 자동 저장됩니다.
  진행하지 않은 라운드는 기록·CSV에서 빈 값으로 남고, 취합 앱이 이를 그대로 인식합니다.
- **이어하기** — 라운드 도중 새로고침·종료해도 시작 화면에서 이어서 진행할 수 있습니다.
- **중복 처리** — 같은 팀·조 기록이 이미 있으면 `덮어쓰기` / `별도 저장`을 선택합니다.
- **기록 화면** — 시작 화면 또는 최종 화면의 `저장된 기록` 버튼
  - 팀별 집계(조 수 / 팀 총 배팅 / 팀 총 잔여), 팀 필터, 개별 삭제, 전체 삭제
- **취합 수단**
  - `결과 복사` / `전체 복사` — `레드팀 1조 | 배팅 5/3/3/3/3 | 총 배팅 17개 | 잔여 8개` 형식
  - `CSV 내보내기` — `chip-dilemma-records-YYYYMMDD.csv` (UTF-8 BOM, Excel 한글 정상)

> **주의:** 조마다 각자 기기를 쓰는 경우 강사 기기에 전체 결과가 자동으로 모이지 않습니다.
> 각 조가 `결과 복사`로 전달하거나 `CSV 내보내기` 파일을 취합해야 합니다.
> 브라우저 데이터 삭제·시크릿 모드 종료 시 저장된 기록도 함께 사라집니다.

## 결과 취합 앱 (`admin.html`)

강사용 대시보드입니다. 조별 앱에는 서버가 없으므로, 각 조의 결과를 이 앱에 모아 합계를 냅니다.

### 결과를 넣는 세 가지 방법

| 방법 | 설명 |
|---|---|
| **붙여넣기** | 각 조가 `결과 복사`한 텍스트를 여러 줄 한꺼번에 붙여넣기 |
| **CSV 파일** | 조별 앱의 `CSV 내보내기` 파일을 업로드 (여러 개 동시 선택 가능) |
| **직접 입력** | 팀·조·라운드별 배팅을 손으로 입력 (총 배팅/잔여 실시간 계산) |

인식하는 텍스트 형식:

```
레드팀 1조 | 배팅 5/3/3/3/3 | 총 배팅 17개 | 잔여 8개     ← 결과 복사 형식
레드팀,1,5,3,3,3,3,17,8,2026-09-09 15:30                 ← CSV 형식
레드 1 5 3 3 3 3                                          ← 느슨한 형식
```

같은 팀·같은 조가 다시 들어오면 최신 값으로 덮어씁니다.
인식하지 못한 줄은 이유와 함께 표시하고, 나머지 줄은 정상 처리합니다.

### 보여주는 것

- **스탯 타일** — 취합된 조 수, 전체 배팅, 전체 잔여, 조 평균 잔여
- **팀별 합계** — 팀 총 배팅(막대), 총 잔여, 소진율(= 총 배팅 ÷ 조 수 × 25)
- **라운드별 팀 배팅** — 5라운드 × 3팀 그룹 막대 + 동일 값의 표
- **조별 결과 표** — 라운드별 배팅·총 배팅·잔여, 머리글 클릭 정렬, 행 삭제
- **라운드별 승패** — 라운드별 팀 합계, 라운드 승리 팀, 누적 승수, 팀별 승수 타일
- **최종 결과** — 승리 팀(3승 달성 라운드 포함) → 그 팀 내 잔여 최다 조
- **취합 결과 CSV 내보내기** — 조별 상세 + 팀 합계

### 승리 조건

1. **라운드 승리** — 그 라운드에서 팀 소속 각 조가 배팅한 칩의 **합계가 가장 많은 팀**이 승리
2. **최종 승리** — 5라운드 중 **3개 라운드를 먼저 이긴 팀**이 최종 승리, 게임 종료
3. **우승 조** — 최종 승리한 팀 안에서 **잔여 칩이 가장 많은 조**

3승이 3라운드나 4라운드에서 확정되면 이후 라운드는 진행하지 않습니다.
확정 이후의 라운드 행은 표에서 흐리게 표시하고 판정에 반영하지 않습니다.

### 판정이 보류되는 경우

| 상황 | 처리 |
|---|---|
| 라운드 합계가 동점 | **어느 팀에도 승수를 주지 않고** "동점 · 규칙 미정"으로 표시 |
| 3승 팀이 없음 | "아직 결정되지 않았습니다"와 현재 선두 표시 |
| 총 배팅 25개 초과 행 | 해당 행을 붉게 표시하고 팀별 합계·승패 영역에 경고 |
| 라운드별 데이터가 들어온 조 수가 팀마다 다름 | 어느 라운드에서 몇 개 조가 빠졌는지 경고 |

> 동점 라운드의 처리 규칙은 정해진 바 없습니다. 별도 기준이 생기면 반영해야 합니다.

## 색상 선택 근거

팀 색상(`#e2444b` / `#f0b429` / `#2f7ae5`)은 게임의 팀 정체성이므로 고정입니다.
시각화 팔레트 검증 결과는 다음과 같습니다.

| 팔레트 | 명도 밴드 | 색각이상 분리도(deutan) | 대비 |
|---|---|---|---|
| 옐로 `#f0b429` (채택) | 실패 | **통과** ΔE 19.6 | 통과 |
| 옐로 `#b8830a` (밴드 충족) | 통과 | **실패** ΔE 4.8 | 통과 |

밴드를 맞추면 적록색각이상에서 레드와 구분되지 않으므로, 판독성에 직접
영향을 주는 색각 분리도를 우선해 원래 색을 유지했습니다. 대신 보조 인코딩으로
범례, 직접 라벨, 동일 값의 표 뷰를 항상 함께 제공합니다. 다크 배경 전용 설계입니다
(라이트 배경에서는 옐로의 대비가 1.82로 부족합니다).

## 입력 검증

- 공백, 소수, 음수 입력 차단
- 배팅 칩은 현재 보유 칩(1라운드 25개, 이후 남은 칩) 초과 불가
