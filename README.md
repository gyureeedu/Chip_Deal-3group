# 칩의 딜레마 (Chip Dilemma)

게임 점수(칩) 입력 웹 애플리케이션. 의존성 없는 단일 HTML 파일입니다.

## 배포 주소

각 조가 이 주소로 접속하면 됩니다. 로그인 불필요.

- 프로덕션 브랜치: `claude/nifty-heisenberg-qspqy5` (저장소 기본 브랜치)
- 이 브랜치에 푸시하면 자동으로 재배포됩니다.

## 로컬 실행

`index.html`을 브라우저로 열면 바로 동작합니다. (설치·빌드 불필요)
로컬 확인용으로는 아래처럼 띄울 수 있습니다.

```
npx http-server -p 8080
```

> 저장 기능(localStorage)은 `http(s)://`로 접속할 때 가장 안정적입니다.
> `file://`로 직접 열면 브라우저·설정에 따라 저장이 차단될 수 있으며,
> 이 경우 앱이 시작 화면에 경고를 표시하고 게임 진행만 가능합니다.
> 실제 수업에서는 위 배포 주소를 사용하세요.

## 진행 흐름

1. **팀 선택** — 레드팀 / 옐로팀 / 블루팀
2. **조 이름 입력** — 예) `1` 입력 시 "레드팀 1조"로 셋팅
3. **셋팅 확인** — 초기 칩 25개 지급 안내 및 규칙 안내
   - 5개 라운드 동안 25개의 칩에서 배팅
   - 우리 조가 우승하려면 먼저 우리 팀이 승리해야 함
   - 팀 승리 → 칩을 많이 배팅 / 조 우승 → 칩을 많이 남김
4. **라운드 1~5 반복**
   - `N라운드 시작` 버튼
   - 배팅할 칩 입력 (남은 칩 수를 초과할 수 없음)
   - "남은 칩의 갯수는 00개 입니다. 칩을 배팅하시겠습니까?" 확인
     - **예** → "N개의 칩을 배팅하였습니다. 남은 칩의 갯수는 00개 입니다."
     - **아니오** → 칩 갯수 재입력
5. **최종 결과** — 남은 칩의 갯수 + 라운드별 배팅 기록 + 자동 저장

## 조별 결과 저장

브라우저 `localStorage`에 저장합니다. 서버가 없으므로 **저장한 그 기기에서만** 보입니다.

| 항목 | 저장 키 | 내용 |
|---|---|---|
| 완료 기록 | `chipDilemma.records.v1` | 팀, 조, 라운드별 배팅, 총 배팅, 잔여 칩, 저장 시각 |
| 진행 상태 | `chipDilemma.progress.v1` | 현재 팀·조·라운드·잔여 칩 (완료 또는 재시작 시 삭제) |

- **자동 저장** — 5라운드를 마치면 결과가 자동 저장됩니다.
- **이어하기** — 라운드 도중 새로고침·종료해도 시작 화면에서 이어서 진행할 수 있습니다.
- **중복 처리** — 같은 팀·조 기록이 이미 있으면 `덮어쓰기` / `별도 저장`을 선택합니다.
- **기록 화면** — 시작 화면 또는 최종 화면의 `저장된 기록` 버튼
  - 팀별 집계(조 수 / 팀 총 배팅 / 팀 총 잔여), 팀 필터, 개별 삭제, 전체 삭제
- **취합 수단**
  - `결과 복사` / `전체 복사` — `레드팀 1조 | 배팅 5/3/3/3/3 | 총 배팅 17개 | 잔여 8개` 형식
  - `CSV 내보내기` — `chip-dilemma-records-YYYYMMDD.csv` (UTF-8 BOM, Excel 한글 정상)

> **주의:** 조마다 각자 기기를 쓰는 경우 강사 기기에 전체 결과가 자동으로 모이지 않습니다.
> 각 조가 `결과 복사`로 전달하거나 `CSV 내보내기` 파일을 취합해야 합니다.
> 브라우저 데이터 삭제·시크릿 모드 종료 시 저장된 기록도 함께 사라집니다.

## 입력 검증

- 공백, 소수, 음수 입력 차단
- 배팅 칩은 현재 보유 칩(1라운드 25개, 이후 남은 칩) 초과 불가
