# 칩의 딜레마 (Chip Dilemma)

게임 점수(칩) 집계 웹 애플리케이션. 의존성 없는 단일 HTML 파일입니다.

## 로컬 실행

`index.html`(통합 진행 앱)을 브라우저로 열면 바로 동작합니다. (설치·빌드 불필요)
로컬 확인용으로는 아래처럼 띄울 수 있습니다.

```
npx http-server -p 8080
```

> 저장 기능(localStorage)은 `http(s)://`로 접속할 때 가장 안정적입니다.
> `file://`로 직접 열면 브라우저·설정에 따라 저장이 차단될 수 있으며,
> 이 경우 앱이 시작 화면에 경고를 표시하고 게임 진행만 가능합니다.
> 실제 수업에서는 위 배포 주소를 사용하세요.

## 통합 진행 앱 (`index.html`, 메인)

강사 기기 한 대에서 **팀 지정 → 조 이름 입력 → 라운드 진행 → 승패 판정**까지 모두 처리합니다.
취합 앱(`admin.html`)과는 독립적으로 동작하며, 서로 데이터를 공유하지 않습니다.

### 진행 흐름

1. **팀 지정** — 레드 / 블루 / 옐로 / 블랙 중 **2개 또는 3개** 선택
2. **조 갯수 지정** — 한 팀에 구성될 조의 갯수(1~6개) 선택, 선택한 모든 팀에 동일 적용
3. **조 이름 입력** — 팀별로 조 갯수만큼 입력, 비워 두면 `1조, 2조…`로 자동 지정
   (같은 팀 안에서 이름이 겹치면 진행되지 않습니다)
4. **라운드 1~5** — 모든 조의 배팅을 한 화면에서 입력 → `라운드 마감`
   - 팀별 합계가 입력 중 실시간으로 표시됩니다
   - 마감 확인은 앱 내부 모달(`예` / `아니오`)로 받습니다.
     브라우저 `confirm()`은 iframe 미리보기 환경에서 차단되므로 쓰지 않습니다
   - 마감 후에는 수정할 수 없습니다
5. **라운드 결과** — 승리 팀 + 합계, **가장 적게 낸 팀과 그 칩의 갯수**, 팀별 잔여 칩, 누적 승수
6. **최종 결과** — 게임이 끝난 라운드를 마감하면 결과 화면으로 바로 넘어갑니다
   - 최종 승리 팀(공동 가능) → 잔여 칩이 가장 많은 **우승 조**
   - 마지막 라운드 요약(승리 팀 / 가장 적게 낸 팀), 누적 승수
   - 라운드별 팀 합계표, 조별 상세표
   - `CSV 내보내기` / `결과 복사`
   - `리셋하고 새 게임 시작` — 확인 모달 후 기록을 지우고 팀 지정 화면으로

### 규칙

- 각 조에 칩 **25개** 지급, 배팅한 칩은 **돌려받지 않고 차감**
- **라운드 승리** — 같은 팀 소속 조들이 배팅한 칩의 **합계가 가장 많은 팀**
- **최종 승리** — **먼저 3승**한 팀. 3라운드·4라운드에서 확정되면 남은 라운드는 진행하지 않습니다
- 진행 상태 저장 키는 `chipDilemma.game.v3` (결과 구조 변경으로 이전 버전 기록은 무시)
- **우승 조** — 최종 승리 팀에서 **칩을 가장 많이 남긴 조**

### 동점 처리 규칙

| 상황 | 처리 |
|---|---|
| 라운드 합계 동점 | 동점 팀 **모두 1승** (공동 승리로 표시) |
| 3승 팀이 여러 팀 동시 발생 | **누적 배팅 합계가 많은 팀**이 최종 승리, 그 시점에 게임 종료 |
| 5라운드까지 3승 팀 없음 | **최다 승 팀**이 단독이면 그 팀이 최종 승리 |
| 위에서 승수까지 동률 | **그때까지 배팅한 칩의 누적 합계가 많은 팀**이 최종 승리 |
| 승수·누적 배팅 합계까지 모두 동률 | 해당 팀 **모두 공동 최종 승리** |
| 승리 팀 안에서 잔여 칩 동점 | 해당 조 **모두 우승** (공동 우승으로 표시) |

> 동점 라운드에서 양 팀 모두 승수를 받으므로 3승에 동시 도달할 수 있습니다.
> 이때는 누적 배팅 합계로 가리고, 그것마저 같으면 공동 최종 승리입니다.
> 공동 최종 승리일 때 우승 조는 **공동 승리 팀 전체에서** 잔여 칩이 가장 많은 조로,
> 서로 다른 팀의 조가 함께 우승할 수 있습니다. 판정이 미정으로 남는 경우는 없습니다.

### 입력 검증 / 저장

- 배팅은 **0 이상의 정수**만 허용, 각 조의 **남은 칩 초과 불가**, 빈칸은 마감되지 않음(미배팅은 `0` 입력)
- 진행 상태는 `localStorage`의 `chipDilemma.game.v3`에 저장되어, 새로고침·종료 후 **이어서 진행** 가능
- `새 게임` / `처음부터 다시`를 누르면 저장된 게임이 삭제됩니다

## 결과 취합 앱 (`admin.html`)

강사용 대시보드입니다. 조마다 따로 집계한 결과를 손으로 모아 합계를 낼 때 사용합니다.
메인 진행 앱(`index.html`)으로 게임을 진행하면 판정까지 자동이므로 이 앱은 필요하지 않습니다.

### 결과를 넣는 세 가지 방법

| 방법 | 설명 |
|---|---|
| **붙여넣기** | 아래 형식의 텍스트를 여러 줄 한꺼번에 붙여넣기 |
| **CSV 파일** | 같은 형식의 CSV 파일 업로드 (여러 개 동시 선택 가능) |
| **직접 입력** | 팀·조·라운드별 배팅을 손으로 입력 (총 배팅/잔여 실시간 계산) |

인식하는 텍스트 형식:

```
레드팀 1조 | 배팅 5/3/3/3/3 | 총 배팅 17개 | 잔여 8개     ← 텍스트 형식
레드팀,1,5,3,3,3,3,17,8,2026-09-09 15:30                 ← CSV 형식
레드 1 5 3 3 3 3                                          ← 느슨한 형식
```

같은 팀·같은 조가 다시 들어오면 최신 값으로 덮어씁니다.
인식하지 못한 줄은 이유와 함께 표시하고, 나머지 줄은 정상 처리합니다.

### 보여주는 것

- **스탯 타일** — 취합된 조 수, 전체 배팅, 전체 잔여, 조 평균 잔여
- **팀별 합계** — 팀 총 배팅(막대), 총 잔여, 소진율(= 총 배팅 ÷ 조 수 × 25)
- **라운드별 팀 배팅** — 5라운드 × 3팀 그룹 막대 + 동일 값의 표
- **조별 결과 표** — 라운드별 배팅·총 배팅·잔여, 머리글 클릭 정렬, 행 삭제
- **라운드별 승패** — 라운드별 팀 합계, 라운드 승리 팀, 누적 승수, 팀별 승수 타일
- **최종 결과** — 승리 팀(3승 달성 라운드 포함) → 그 팀 내 잔여 최다 조
- **취합 결과 CSV 내보내기** — 조별 상세 + 팀 합계

### 승리 조건

1. **라운드 승리** — 그 라운드에서 팀 소속 각 조가 배팅한 칩의 **합계가 가장 많은 팀**이 승리
2. **최종 승리** — 5라운드 중 **3개 라운드를 먼저 이긴 팀**이 최종 승리, 게임 종료
3. **우승 조** — 최종 승리한 팀 안에서 **잔여 칩이 가장 많은 조**

3승이 3라운드나 4라운드에서 확정되면 이후 라운드는 진행하지 않습니다.
확정 이후의 라운드 행은 표에서 흐리게 표시하고 판정에 반영하지 않습니다.

### 판정이 보류되는 경우

| 상황 | 처리 |
|---|---|
| 라운드 합계가 동점 | **어느 팀에도 승수를 주지 않고** "동점 · 규칙 미정"으로 표시 |
| 3승 팀이 없음 | "아직 결정되지 않았습니다"와 현재 선두 표시 |
| 총 배팅 25개 초과 행 | 해당 행을 붉게 표시하고 팀별 합계·승패 영역에 경고 |
| 라운드별 데이터가 들어온 조 수가 팀마다 다름 | 어느 라운드에서 몇 개 조가 빠졌는지 경고 |

> 동점 라운드의 처리 규칙은 정해진 바 없습니다. 별도 기준이 생기면 반영해야 합니다.

## 색상 선택 근거

팀 색상(`#e2444b` / `#f0b429` / `#2f7ae5`)은 게임의 팀 정체성이므로 고정입니다.
통합 진행 앱의 블랙팀은 다크 배경에서 검정을 그대로 쓸 수 없어 무채색 밝은 회색
`#b9c0dc`로 표시합니다. 무채색이라 색각이상에서도 다른 세 색과 혼동되지 않습니다.
시각화 팔레트 검증 결과는 다음과 같습니다.

| 팔레트 | 명도 밴드 | 색각이상 분리도(deutan) | 대비 |
|---|---|---|---|
| 옐로 `#f0b429` (채택) | 실패 | **통과** ΔE 19.6 | 통과 |
| 옐로 `#b8830a` (밴드 충족) | 통과 | **실패** ΔE 4.8 | 통과 |

밴드를 맞추면 적록색각이상에서 레드와 구분되지 않으므로, 판독성에 직접
영향을 주는 색각 분리도를 우선해 원래 색을 유지했습니다. 대신 보조 인코딩으로
범례, 직접 라벨, 동일 값의 표 뷰를 항상 함께 제공합니다. 다크 배경 전용 설계입니다
(라이트 배경에서는 옐로의 대비가 1.82로 부족합니다).
